# Hiking Planner — дорожная карта

**Версия плана:** 0.1, 18.11.2026. Этапы описывают **проверяемые результаты**, не календарные обещания.  
**Приоритет:** пригодное к использованию приложение для одного туриста, без необязательной серверной инфраструктуры.

## Этап 0. Технический фундамент / документация

**Результат:** оформлены README, техническое задание, архитектура, проектная модель данных, каталог внешних источников, план этапов и `PROJECT_STATE.md`.

**Приёмка:** файлы доступны в приватном репозитории `socman2023/hiking-planner`, внутренние ссылки разрешаются, нет утверждений о якобы работающей сборке, определены ограничения источников и личных данных.

**Не входит:** работающий интерфейс, реальная БД, авторизация, публикация, импорт реального Excel или подтверждение формул по подлиннику.

## Этап 1. Рабочий каркас и управление походами

- Инициализация Vite + React + TypeScript (strict), npm lockfile, линтер/форматтер, Vitest/RTL, Playwright-smoke.
- Адаптивная оболочка в выбранной палитре (вдохновлена демонстрационным HTML, название только Hiking Planner); русский язык.
- Модуль Trip/TripDay: создать, открыть, отредактировать, дублировать, архивировать, удалить поход.
- Настройки количества дней, дат и характера дня; безопасное расширение/сокращение.
- IndexedDB/Dexie с первой миграцией; резервный экспорт/импорт основного набора данных.
- Автосохранение с подтверждаемым статусом; пустые состояния; ошибки и загрузка.
- GitHub Actions для `npm ci`, тестов и сборки после создания кода.

**Приёмка E1:** сценарии 1, 2, 9 и 10 из REQUIREMENTS; приложение открывается локально, сохраняет два независимых похода после перезапуска, миграция и бэкап проверены, сборка и тесты проходят. Проверить мобильную навигацию на 390px.

## Этап 2. Постоянная библиотека и управляемые источники

- CRUD + поиск/фильтры: продукты, фасовки, снаряжение, собственные экземпляры, рецепты/ингредиенты, лекарства/изделия.
- Справочные атрибуты/источники с датой и лицензией; поля `unknown` не превращаются в 0.
- Импорт пользовательских файлов с предпросмотром; точный маппинг прежних XLSX — **после получения подлинника**.
- Карточки товара/препарата, собственные значения и подтверждение внешних сведений.
- Экспорт соответствующих каталогов в JSON/CSV.

**Приёмка E2:** один и тот же элемент библиотеки доступен для двух походов; редактирование походного статуса не изменяет библиотеку; фасовки и массы не смешиваются.

## Этап 3. Меню, раскладка и вес продуктов

- Гибкий дневной конструктор меню, ингредиенты и блюда; произвольное число приёмов пищи.
- Чистые расчёты калорий, БЖУ, съедобной и переносимой массы, закупок с округлением упаковок, остатков.
- Редактируемая модель воды/приготовления и топлива, без недостоверной зависимости газа от массы порции.
- Покрытие расчётов граничными тестами: неизвестные нутриенты, нулевые порции, дробные массы, упаковки, изменения длительности.
- Печатная раскладка и первоначальный CSV.

**Приёмка E3:** изменение порции пересчитывает все сводки; при двух фасовках закупка корректна; исходные блюда остаются в библиотеке.

## Этап 4. Личное снаряжение и подготовка

- Создание походного комплекта из собственного/каталожного снаряжения, масса, количество, размещение и статусы сборов.
- Чек-лист с поиском, фильтрами, массовыми действиями, подтверждением, отменой.
- Производные показатели: рюкзак, вещи на себе, расходники, известный/неизвестный вес.
- Дополнительные калькуляторы (автономность электроники) без обязательных внешних сервисов.

**Приёмка E4:** ни одно из состояний упаковки не меняет автоматически наличие вещи; вес рюкзака отделён от массы носимых вещей; неизвестный вес не считается нулевым.

## Этап 5. Карта, GPX и маршрут

- Реальная карта Leaflet с разрешённым поставщиком тайлов и атрибуцией OSM.
- Многодневный трек, точки, участки, импорт и экспорт GPX/GeoJSON.
- Профиль высот по имеющимся данным, дистанции, отмеченные ночёвки и водоисточники.
- Локальная библиотека маршрутов/точек, связи с походами и заметками.

**Приёмка E5:** GPX импортируется и повторно экспортируется без критической потери координат, дневные участки различимы; при отсутствии высот система явно сообщает об этом.

## Этап 6. Интернет-интеграции

- Начать с Open-Meteo (прогноз по точкам и датам), Open Food Facts (явный поиск) и OSM/Overpass (объекты/маршруты).
- Поиск источников треков, фото и описаний: Wikimedia/OSM и ссылки на внешние сервисы.
- Поиск производителя оборудования: официальные сайты и разрешённые API; там, где API нет — ссылочный/ручной путь.
- Медицинский поиск: DailyMed и ссылки на национальные официальные реестры; локальная карточка с версией инструкции.
- Адаптеры и локальный кэш с provenance, rate limit, обработкой отказов, предосмотром до импорта.
- Внешние инструкции и данные не должны автоматически подменять подтверждённые пользовательские записи.

**Приёмка E6:** по одному работающему публичному адаптеру в каждой подтверждённой категории; провайдеры, которые недоступны из браузера, документированы и не имитируются. В режиме offline доступен ранее сохранённый контент.

## Этап 7. Аптечка, транспорт, финансы, проверки

- Формирование аптечки из каталога с конкретными сроками годности и местом размещения.
- Транспортные плечи, время/пересадки, бюджет план/факт с `unknown / not_spent / recorded`.
- Набор прозрачных проверок полноты данных: срок годности, статус упаковки, калорийность, противоречия маршрута, отсутствие цены/массы и т. д.
- План безопасности одиночного похода (контрольные сроки связи, контакты, PDF/печать), без обещания аварийной связи.

**Приёмка E7:** фиктивное «автоисправление» не закрывает проблему; пустая фактическая сумма не равна 0; точная дата годности не подставляется программой.

## Этап 8. PWA, стабильность и публикация при необходимости

- Обслуживание оболочки приложения в offline, проверка поведения без сети.
- Адаптивность, доступность, скорость, ошибки, версионированные миграции, полные бэкапы с вложениями.
- Импорт/экспорт XLSX/CSV/GPX/GeoJSON/PDF в соответствующих модулях.
- Мобильные сценарии и установка PWA по HTTPS; выбор статического хостинга **только при готовности к публикации**.
- Офлайн-карты — исключительно после выбора подходящего лицензированного источника/формата.

**Приёмка E8:** восстановление полной копии, переход между версиями данных, отсутствие блокировок при недоступном API, работоспособность на мобильном браузере и без сети.

## Отложено

- Участники, совместная работа, распределение снаряжения и финансов.
- Авторизация, облачная синхронизация, CRDT, push-уведомления, полноценная GPS-навигация.
- Платные API/коммерческое распространение/маркетплейсы.

## Порядок работы и ответственность

**ChatGPT / разработка:** требования и документация; код, миграции, тесты, CI, исправления, коммиты, техническая проверка; публикация изменений в GitHub через доступные инструменты. Не заявлять тесты успешными без фактического выполнения.

**Владелец проекта:** утверждение спорных продуктовых решений, проверка интерфейса на своих устройствах, предоставление оригинальных Excel-примеров для точного маппинга импорта, выбор конкретных сторонних аккаунтов/ключей только при появлении реальной необходимости. Не нужно вручную создавать код или оплачивать инфраструктуру для этапов 0–1.

### Каждая итерация должна содержать

1. Цель и список изменяемых модулей.
2. Изменения в коде + проверки и отчёт о фактическом результате.
3. Небольшой коммит (или логически связанный набор коммитов).
4. Обновление `docs/PROJECT_STATE.md`: текущая ветка/HEAD, выполнено, остаётся, известные проблемы, следующее действие.
5. Явное разделение «реализовано», «планируется» и «требует проверки».

## Риски и ответные меры

| Риск | Мера |
|---|---|
| Поддержка интернет-сервисов меняется | Независимые адаптеры, кэш, ручной импорт |
| Необоснованные/старые данные | Источник, дата, неизвестное значение, подтверждение |
| Потеря браузерных данных | Регулярный JSON-бэкап + тест восстановления |
| Ошибки расчётов | Чистые функции + unit-тесты, фиксированные единицы |
| Проблемы офлайн-карт | Не использовать массовое скачивание с публичных OSM |
| Перегруженность интерфейса | Solo-first, основная навигация и прогрессивное раскрытие |
| Испорченный импорт Excel | Предпросмотр, отчёт о маппинге, атомарный импорт |
| Разрастание затрат | Нет сервера и платных сервисов без отдельного согласования |
