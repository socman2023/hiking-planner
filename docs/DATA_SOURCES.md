# Hiking Planner — интернет-источники и ограничения

**Проверено по публичной документации:** 18.11.2026. Это перечень кандидатов, а не обещание, что каждый API допускает запросы из браузера во всех регионах. CORS, условия использования, покрытие и актуальные лимиты проверяются автоматизированным тестом перед включением адаптера.

## 1. Правила интеграции

- Сначала бесплатные и официальные источники, затем сторонние каталоги со свободным/разрешённым доступом.
- Не делать скрытый парсинг закрытых сайтов, социального контента, магазинов или личных данных. Учитывать robots/ToS и лицензии.
- Для каждого провайдера: ссылка на документацию, доступность, CORS, лимиты, политика кэширования, ссылка на атрибуцию и дата последней проверки.
- API-результат => предварительная карточка => сравнение с текущей => **подтверждение пользователя** => запись в IndexedDB.
- Если доступ запрещён или сайт не имеет публичного API, использовать открытие URL и ручной импорт, не обещать единого «поиска по всему интернету».
- Отображать источник и дату для погоды, цен, маршрутов, характеристик, фотографий, лекарственных инструкций.
- Для данных со сроком актуальности (прогноз, цены, закрытие троп) показывать статус «устарело / проверить заново».

## 2. Погода

### Open-Meteo (первый адаптер)
- Сайт: https://open-meteo.com/
- API: https://open-meteo.com/en/docs
- Назначение: прогноз по координатам и датам в пределах фактического прогнозного горизонта (до 16 дней), почасовая температура, ветер, осадки и др.
- Бесплатный доступ заявлен для некоммерческого использования и ограничен по нагрузке; проверять условия при смене способа распространения приложения.
- Нельзя показывать «прогноз на конкретную дату через 3 месяца» — в этом случае нужны отдельно помеченные исторические/климатические данные, не подмена ими прогноза.
- Снимки погодных данных сохранять с координатой, рассчитанной высотой, `retrievedAt`, моделью/источником и часовым поясом.

### MET Norway (возможный резерв)
- Документация: https://api.met.no/
- Применять при соблюдении идентификации клиента, кеширования, политики API; пригодность для прямого браузерного доступа установить отдельно.

## 3. Карты, треки, места, высоты

### OpenStreetMap / Overpass
- OSM: https://www.openstreetmap.org/
- Overpass: https://wiki.openstreetmap.org/wiki/Overpass_API
- Назначение: размеченные тропы, турмаршруты, места ночёвок, источники, броды, перевалы, вершины и др.
- Публичные экземпляры Overpass ограничены; запросы ограничивать районом, временем и объёмом, использовать кэш и уважать HTTP 429.
- OSM — база геоданных, а не гарантия полноты или пригодности объекта для прохождения.

### Nominatim — поиск географических названий
- Политика: https://operations.osmfoundation.org/policies/nominatim/
- Публичный endpoint имеет абсолютное ограничение не более одного запроса/с для приложения и запрещает ряд сценариев (в частности, бездумное autocomplete). Для масштабного поиска подбирать другого провайдера либо свой сервер.
- Для первого релиза можно обойтись поиском по небольшому числу явных запросов.

### Тайлы OSM и офлайн
- Правила: https://operations.osmfoundation.org/policies/tiles/
- Публичный `tile.openstreetmap.org` запрещает предзагрузку районов и массовое скачивание для офлайна. Для офлайн-карт требуется другой лицензированный поставщик/готовый локальный пакет.
- Любая подложка должна отображать требуемую атрибуцию. Leaflet — библиотека визуализации, а не поставщик карт или маршрутизации.

### Высоты
- Open Topo Data: https://www.opentopodata.org/
- Сервис с публичным API высот (с условиями и возможными ограничениями производительности). Высоты — модельные, не геодезические измерения; хранить источник.
- Большие массивы точек обрабатывать партиями и фильтровать аномалии.

### GPX / внешние сайты
- Поддерживать локальный импорт GPX и GeoJSON и экспорт собственного трека.
- Waymarked Trails, Wikiloc, Komoot, Strava, форумы, блоги, соцсети — источник ссылок и ручного импорта там, где отсутствует подходящий общедоступный API. Не заявлять автоматизированное извлечение чужих пользовательских треков без разрешения и авторизации.

## 4. Продукты питания

### Open Food Facts
- Документация: https://openfoodfacts.github.io/documentation/docs/
- API: https://openfoodfacts.github.io/documentation/docs/Product-Opener/api/
- Назначение: штрихкод, название, бренд, упаковка, нутриенты, изображения, состав при наличии.
- API имеет rate limits; поиск выполняется по явной команде с debounce/кэшем и ограниченным количеством запросов.
- Значения на 100 г и на порцию могут сосуществовать; нормализовать только если обозначена база и единицы.
- Цены, упаковки и сведения из пользовательских карточек могут быть устаревшими/неполными.

### USDA FoodData Central
- API: https://fdc.nal.usda.gov/api-guide/
- Назначение: справочные нутриенты базовых и брендированных продуктов.
- Требуется API-key; default limit указан как 1000 запросов/час на IP. Секретный ключ не встраивать в публичную сборку. Подключить позже только после решения по безопасной авторизации и пригодности для браузера.

### Производители сублимированного питания / магазины
- Прямая загрузка только с официально разрешённых API или предоставленных файлов. Иначе открытие производителя/магазина и полуавтоматический ввод пользователем.
- Хранить варианты упаковок отдельно, цену с датой и магазином, массу нетто/тары, БЖУ/ккал и инструкцию приготовления.
- Не смешивать значения «сухое» и «готовое» блюдо.

## 5. Снаряжение и приборы

- Приоритет: официальный сайт производителя и публичные технические PDF/страницы, затем открытые каталоги с разрешённой лицензией.
- Open Icecat: https://icecat.com/ и его условия/доступность исследовать на момент реализации конкретного адаптера.
- Нет универсального бесплатного API для всех мировых и региональных туристических товаров. Для сайтов без API: ссылка/ручной импорт, фото только с разрешением.
- Производитель, модель, вес производителя и **вес конкретного собственного экземпляра** различаются.

## 6. Лекарства и медицинские принадлежности

### DailyMed
- API: https://dailymed.nlm.nih.gov/dailymed/app-support-web-services.cfm
- Официальные структурированные инструкции SPL для препаратов, доступных в соответствующей системе; может не охватывать конкретные препараты других стран.
- Хранить версию, ссылку, дату загрузки, оригинальные противопоказания и условия хранения; PDF/локальный документ — только по разрешению источника.

### Национальные реестры и другие источники
- ГРЛС РФ: https://grls.rosminzdrav.ru/
- Европейское агентство EMA: https://www.ema.europa.eu/
- Реестр Литвы: https://vapris.vvkt.lt/
- РЛС: https://www.rlsnet.ru/ (неофициальные относительно госреестра справочные материалы; лицензия/условия использования требуют отдельной проверки).
- Для реестров без открытого пригодного API в браузере: ссылки на первоисточник и разрешённое ручное сохранение сведений; не объявлять доступ к «официальному API», пока он не проверен.
- Лекарственные инструкции обновляются; срок годности **конкретной упаковки** вводится пользователем по этикетке. Никаких автоматически выдуманных дат, дозировок и назначений.

## 7. Фото, географические материалы и описания

- Wikipedia и MediaWiki API: https://www.mediawiki.org/wiki/API:Main_page
- Wikimedia Commons: https://commons.wikimedia.org/
- Wikidata: https://www.wikidata.org/
- Данные для конкретного объекта: координаты, описание, фото, автор, лицензия, дата съёмки/наблюдения, URL. Проверять конкретную лицензию каждого фото и соблюдать атрибуцию.
- Mapillary и туристические сайты — только по актуальным разрешённым правилам; для закрытого контента хранить ссылку/описание, не обходить API.
- Свежесть сезонных отчётов хранить отдельно от постоянных характеристик объекта.

## 8. Транспорт, безопасность и опасности

- Публичного универсального бесплатного транспорта API для всех регионов нет. Сначала ручной ввод, источники-ссылки и, по возможности, открытые GTFS-расписания.
- Официальные предупреждения МЧС, заповедников, лавинных/погодных служб — по выбранному региону, если источники доступны. Не выдавать отсутствие предупреждения за гарантию безопасности.
- Для одиночного туриста предусмотреть экспорт контрольного плана маршрута и времени связи доверенному лицу без «автоматического SOS», если нет рабочего канала связи.

## 9. Проверка перед интеграцией (чек-лист)

1. Документация доступна, условия разрешают наш тип некоммерческого использования?
2. Тест реального запроса выполняется из браузера (CORS), нет обязательного скрытого ключа?
3. Проверен лимит частоты и есть механизм кэширования/429?
4. Данные совпадают по единицам и форме (`per100g`, нетто/брутто, локальная дата)?
5. Есть URL, источник, лицензия, дата и возможность показать пользователю до записи?
6. Есть обработка ошибок, неполноты, устаревания и offline?
7. Нет публикации чувствительных данных о маршруте/здоровье третьим лицам без необходимости?

Кандидат, не прошедший проверку, не включается в автоматический режим. Альтернатива — открыть источник и выполнить ручной импорт с указанием происхождения.
